# 老人监护云平台业务流程（管理台 / 家属 / 硬件 / App）

> 适用版本：本地与云端统一 18080 端口；全局角色为 admin / family，家属成员权限一致（SPEC 04）。
> 本文用于课设答辩演示与三方联调对齐，不构成生产级方案。

## 1. 核心关系模型

系统里有两条互相独立、容易混淆的“绑定”：

| 关系 | 存储位置 | 回答的问题 | 谁能操作 |
| --- | --- | --- | --- |
| 账号 ↔ 老人 | `elder_access`（账号-老人关联） | 哪些账号能看这位老人 | admin 或该老人的家属成员 |
| 设备 ↔ 老人 | `devices.elder_id` | 设备上报的数据算在哪位老人名下 | 仅 admin |

- 账号只有两种全局角色：`admin`（平台管理员）与 `family`（家属，老人与家属共用此账号）。
- 家属成员不区分层级（SPEC 04）：只要与老人建立关联，就可以查看与维护该老人（含编辑档案、管理监护成员）；`elder_access` 不再有角色列。
- 设备不需要绑定到账号；设备只绑定到老人。家属看到的是“老人名下的设备”，不是“自己的设备”。
- 解绑设备不会删除历史遥测与事件；解绑成员不会删除老人任何数据。

## 2. 权限矩阵

| 能力 | admin | family（家属成员） |
| --- | --- | --- |
| 查看老人档案 / 健康 / 事件 / 告警 | 全量 | 仅关联老人 |
| 编辑老人档案 | 是 | 是 |
| 删除老人档案 | 是 | 否 |
| 紧急联系人读写 | 是 | 是 |
| 电子围栏读写 | 是 | 是 |
| 确认告警 | 是 | 是 |
| 查看 / 管理监护成员 | 是 | 是 |
| 查看绑定设备（只读） | 是 | 是 |
| 注册 / 绑定 / 解绑设备 | 是 | 否 |
| 用户列表 / 编辑用户 / 重置密码 | 是 | 否 |
| 查看账号监护关系（用户列表） | 是 | 否 |

## 3. 管理员流程

1. 登录管理台（seed 账号，`SEED_ADMIN_*`）。
2. 新建老人档案（也可由家属自建，家属创建者自动与该老人建立关联）。
3. 设备管理页注册设备：填写 `device_uid`、类型（esp32 / phone / wearable）、型号。
4. 把设备绑定到老人；一台设备同一时刻只能绑定一位老人。
5. 在老人详情「监护成员」Tab 添加家属（admin 与该老人的任意家属成员都有此入口）：
   - 选择家属账号并保存，保存后立即生效（不再需要选择角色）；
   - 成员可以随时移除（取消绑定），包括最后一位成员；列表清空后老人仅 admin 可见，可随时由 admin 重新添加；
   - 用候选搜索接口按关键字检索要添加的家属账号，无需用户列表权限。
6. 日常：查看全量看板、处理告警、维护围栏/联系人、编辑用户；所有写操作进审计日志。
7. 设备换人：先「解绑」，再绑定到新老人；历史数据保留在原老人名下。

对应接口：

| 操作 | 接口 |
| --- | --- |
| 监护成员列表 | `GET /api/v1/elders/{elder_id}/access` |
| 监护成员整体替换 | `PUT /api/v1/elders/{elder_id}/access` |
| 候选家属账号检索（admin / 家属） | `GET /api/v1/elders/{elder_id}/access/candidates?q={关键字}` |
| 账号关联的老人（用户列表「监护关系」，仅 admin） | `GET /api/v1/users/{user_id}/elders` |
| 老人绑定设备（只读） | `GET /api/v1/elders/{elder_id}/devices` |
| 注册 / 绑定设备 | `POST /api/v1/devices`、`POST /api/v1/devices/{id}/bind` |
| 解绑设备 | `POST /api/v1/devices/{id}/unbind` |

老人相关接口（`GET/POST /api/v1/elders`、`GET/PUT /api/v1/elders/{elder_id}`）按
关联关系判定可见范围：家属只能看到自己关联的老人，关联即可读取与维护。SPEC 04 起
响应不再返回 `my_role`，管理台也不再显示「我的角色」或按成员角色门控按钮。

## 4. 家属流程

1. 自助注册（`POST /api/v1/auth/register`，固定 family 角色）并登录。
2. 新账号默认看不到任何老人。两种方式获得访问权：
   - 自己新建老人：自动与该老人建立关联（创建人）；
   - 由 admin（或该老人的其他家属成员）在「监护成员」中添加。
3. 查看健康数据、事件、告警；在「告警与事件」页确认告警。
4. 任意家属成员都可继续添加/移除成员，包括移除最后一位（取消绑定，成员列表允许为空）；被移除后 REST 立即 403，WebSocket 可见范围在 30 秒内刷新。

## 5. 硬件设备流程

1. 设备出厂/联调前由 admin 在管理台注册 `device_uid`，并绑定到老人；未注册或未绑定设备的消息会被丢弃并写 WARN 日志。
2. 设备使用共用 MQTT 账号连接 `1883`（明文），上行主题：
   - `iot/v1/{device_uid}/status`：30 秒心跳，刷新在线状态；
   - `iot/v1/{device_uid}/event`：`fall`、`geofence_exit` 等事件。
3. 任何一条合法上行会把设备置为 online；超过 120 秒无消息，平台巡检生成 `device_offline` 告警（约 2 分 15 秒可见）。
4. 跌倒：设备端算法确认后上报 `fall`（critical），平台生成 event → alert → 通知 → WebSocket 推送。
5. 围栏有两种模式，同一设备只需选一种：
   - 设备侧：BLE 连接/断开判定，设备直接上报 `geofence_exit`；
   - 平台侧：设备上报 `location` 遥测，平台按围栏中心 + 半径判定。
   围栏编辑器中的半径仅对上报位置遥测的设备生效。
6. 解绑后设备回到未绑定状态，新的上行消息按未绑定丢弃；历史数据保留。

## 6. 告警处理流程

1. 事件产生：设备事件（fall / sos / geofence_exit / low_battery）或平台规则（低电量、离线、平台侧围栏）。
2. 平台为每条事件生成一条 alert，并按紧急联系人为每位联系人生成一条模拟通知（当前全部写 `sent`）。
3. 管理台 / App 通过 WebSocket 秒级收到新告警，REST 轮询作为兜底。
4. 家属或管理员点击「确认」→ `POST /api/v1/alerts/{id}/ack`：
   - alert 从 `new` 变为 `handled`，记录处理人与时间；
   - 同一事务把对应 event 的 status 从 `new` 置为 `handled`；
   - 重复确认幂等，不重复写审计。
5. 当前未实现真实电话/短信与“超时升级”；成熟产品的做法（主联系人未响应后升级下一位）见第 8 节。

## 7. 答辩演示脚本（本地 18080）

1. `docker compose ps` 确认 backend 有 `0.0.0.0:18080->8000/tcp`，`readyz` 返回全 ok。
2. admin 登录管理台，注册硬件设备 `esp32-demo-0002` 并绑定到演示老人。
3. 用测试账号 `laowang`（登录页第三个快捷登录按钮）登录，在老人详情「监护成员」Tab 搜索并
   添加候选账号 `family-guest`，现场展示候选搜索与添加（admin 与任一家属成员都有该入口）。
4. 硬件上电，管理台确认设备 `online`；触发跌倒，展示 alert 推送与通知记录。
5. `family` 登录管理台「告警与事件」页（默认告警 Tab）确认告警，展示 alert 与 event
   同时变为 `handled`；事件在第二个 Tab 查看完整 Payload。
6. 可选：演示设备解绑 → 设备回到未绑定；重新绑定到另一位老人。
7. 可选：停止心跳 2 分 15 秒，展示 `device_offline` 告警；恢复后设备重新 online。

## 9. 本期演示取舍（已定）

- BLE 围栏：App 端暂不改，用 nRF Connect 等 BLE 调试工具连接/断开来触发
  `geofence_exit`；若 App 组确认已实现 BLE 连接，再切换为 App 直连演示。
- 健康数据：真实硬件 `esp32-demo-0002` 只上报跌倒、围栏与心跳；心率、血氧、
  步数、电量由模拟器 `esp32-demo-0001` 或 seed 数据提供，两台设备可绑定同一位演示老人。
- 设备侧围栏：接受设备直接上报 `geofence_exit`；平台围栏编辑器（中心 + 半径）
  仅对上报 `location` 遥测的设备生效。
- 端口：本地与云端统一 18080；MQTT 仍为 1883，硬件不用改地址。

## 10. 当前边界

- 单实例部署；本地与云端共用 18080，MQTT 固定 1883。
- MQTT 明文、共用账号、无设备级 ACL；固件硬编码服务器地址与口令。
- 通知为 console 模拟；无真实短信/电话/系统推送，App 仅前台弹窗。
- 无字段级共享同意；关联 elder_access 后可见该老人全部历史数据。
- 家属成员不区分权限层级（SPEC 04）：关联即可查看与维护，`elder_access` 无角色列；
  演示账号含测试账号 `laowang`（登录页快捷登录第三个按钮）。
- 告警无超时升级、无关闭动作；`closed` 状态在界面上不再展示。
- 管理台只服务 admin / family（老人侧用 App）：已移除老人只读展示页（旧地址 301 回首页），
  「事件记录」并入「告警与事件」页（`/events` 301 到 `/alerts/?view=events`）。
